## Accessibility Audit: Interview Prep App
**Standard:** WCAG 2.1 AA | **Date:** 2026-06-11 | **Method:** static code review (no rendered-page testing — see "Manual follow-ups")

### Summary
**Issues found:** 11 | **Critical:** 2 | **Major:** 5 | **Minor:** 4 | **Fixed in this pass:** 9

### Findings

#### Perceivable
| # | Issue | WCAG | Severity | Status |
|---|-------|------|----------|--------|
| 1 | Mock answer state (correct/wrong) conveyed by colour only on options | 1.4.1 | 🔴 Critical | ✅ Fixed — sr-only "Correct!/Not quite" suffix on option text |
| 2 | `LevelDots` difficulty indicator invisible to screen readers (hover-only tooltip) | 1.1.1 | 🟡 Major | ✅ Fixed — `role="img"` + `aria-label` |

| # | Issue | WCAG | Severity | Status |

### What was already good
Radix Popover tooltips (keyboard + Escape out of the box) · `aria-expanded`/`aria-controls` on question cards · `aria-live` on answer feedback · default focus outlines not suppressed globally · `aria-label` on icon-only buttons (bookmark, theme, lang, menu) · semantic `<main>`/`<nav>` landmarks.

### Manual follow-ups (cannot be verified statically)
1. **Contrast measurements** — run axe DevTools or the Chrome a11y panel on both themes. Suspects: `text-muted-foreground` on `bg-muted/40` (inactive tabs), `/50`-opacity text, amber/violet tab tints.
2. **Keyboard-only mock run** — full session start-to-finish, both themes.
3. **Zoom 200%** — check the fixed navbar (`pt-[37px]`) doesn't clip content.
4. **Screen reader pass** — NVDA on the questions list: card expand → answer → personal example flow.
